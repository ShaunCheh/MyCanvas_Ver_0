# 图片选中与拖拽方案一

## 目标

在当前画布架构上实现单选图片、高亮蓝边、拖动已选中图片移动其世界坐标，同时保留空白区域拖动画布和现有缩放能力。

## 共享层改造

- 新增 [MyCanvas_Ver_0/Canvas/Core/CanvasInteractionState.swift](MyCanvas_Ver_0/Canvas/Core/CanvasInteractionState.swift)，只保存运行时交互态，例如 `selectedItemID`，不要把选中态塞进 [MyCanvas_Ver_0/Canvas/Core/CanvasImageItem.swift](MyCanvas_Ver_0/Canvas/Core/CanvasImageItem.swift)。
- 在 [MyCanvas_Ver_0/Canvas/Core/CanvasScene.swift](MyCanvas_Ver_0/Canvas/Core/CanvasScene.swift) 增加世界坐标命中和移动 API：`topmostItem(containing:)`、`moveItem(withID:by:)`。命中测试复用现有 `worldFrame`，并按 `orderedItems()` 的逆序处理顶层 item。
- 扩展 [MyCanvas_Ver_0/Canvas/Core/CanvasRenderSnapshot.swift](MyCanvas_Ver_0/Canvas/Core/CanvasRenderSnapshot.swift) 的 `CanvasRenderItem`，增加 `isSelected`。更新 [MyCanvas_Ver_0/Canvas/Core/CanvasRenderer.swift](MyCanvas_Ver_0/Canvas/Core/CanvasRenderer.swift) 的快照生成签名，让 renderer 把 `interaction.selectedItemID` 编进渲染结果。
- 在 [MyCanvas_Ver_0/Platform/Shared/Rendering/CanvasImageLayer.swift](MyCanvas_Ver_0/Platform/Shared/Rendering/CanvasImageLayer.swift) 消费 `isSelected`，绘制蓝色边框，并像现有 `frame/contents/zIndex` 一样缓存上次选中态，避免重复提交边框属性。

## 平台输入契约

- 把 [MyCanvas_Ver_0/Platform/iOS/Canvas/iOSCanvasViewportView.swift](MyCanvas_Ver_0/Platform/iOS/Canvas/iOSCanvasViewportView.swift) 从“直接输出 `onPan`”升级为 pointer 事件源：`onPointerDown`、`onPointerMove`、`onPointerUp`、`onPointerCancel`，继续保留 `onZoom` 和 `onViewportSizeChange`。viewport 只上报触点位置/增量，不自行决定选中或拖哪个 item。
- 对齐 [MyCanvas_Ver_0/Platform/macOS/Canvas/macOSCanvasViewportView.swift](MyCanvas_Ver_0/Platform/macOS/Canvas/macOSCanvasViewportView.swift) 的鼠标输入语义，提供同一套 pointer 回调；`scrollWheel` 继续作为画布平移，`magnify` 继续作为缩放。
- 复用 [MyCanvas_Ver_0/Canvas/Core/CanvasCamera.swift](MyCanvas_Ver_0/Canvas/Core/CanvasCamera.swift) 里的 `viewportToWorld(_:)` / `worldToViewport(_:)` 做坐标转换，不在平台 view 里再发明一套命中坐标系。

## 控制器分流逻辑

- 在 [MyCanvas_Ver_0/Platform/iOS/iOSViewController.swift](MyCanvas_Ver_0/Platform/iOS/iOSViewController.swift) 和 [MyCanvas_Ver_0/Platform/macOS/macOSViewController.swift](MyCanvas_Ver_0/Platform/macOS/macOSViewController.swift) 持有 `CanvasInteractionState`、`lastRenderSnapshot` 和当前 pointer 拖拽上下文。
- `pointerDown` 时基于 `lastRenderSnapshot.items.reversed()` 的 `screenFrame.contains` 做屏幕空间命中：
  - 命中已选中图片：准备进入图片拖拽。
  - 命中未选中图片：准备点击选中。
  - 命中空白区域：准备拖动画布。
- `pointerMove` 时分流：
  - 拖已选中图片：把 viewport 位移转换成世界坐标位移，调用 `scene.moveItem(withID:by:)`。
  - 拖空白区域：沿用当前 `camera` 平移语义，只更新可见区域。
- `pointerUp` 时完成点击选中并刷新高亮；未命中图片时不强行引入其他额外交互。
- `performCanvasRefresh` 统一改成基于 `scene + camera + interaction` 产出 snapshot，并同步更新 `lastRenderSnapshot`，让命中测试始终对齐用户当前看到的 `screenFrame`。

## 实施顺序

1. 先改共享层：交互态、`CanvasScene` 命中/移动、`CanvasRenderItem.isSelected`、`CanvasImageLayer` 蓝边。
2. 再改 iOS：把 viewport 输出升级成 pointer 事件，controller 接入“点击选中 + 拖选中图片 + 空白拖画布”。
3. 再平移到 macOS：沿用同一套 controller 语义，把鼠标 down/drag/up 接到共享交互流。
4. 最后做构建与交互验证，确认不影响现有导图、缩放和画布平移。

## 验证要点

- 点击图片后，只有该图片显示蓝色边框。
- 拖动已选中图片时，图片位置变化，`camera.center` 不应被同时拖动。
- 在空白区域拖动时，仍然只移动可见区域，不改变图片世界坐标。
- pinch / scroll / magnify 行为保持原样。
- iOS 和 macOS 的选中、高亮、拖拽语义保持一致。

## 风险控制

- 不把选中态写进 `CanvasImageItem`，避免文档数据和运行时交互状态耦合。
- 不使用 `CALayer.hitTest` 作为数据真相，命中一律基于 renderer 产出的 `screenFrame`。
- 在 pointer 迁移完成前，平台 view 的旧 `onPan` 路径可以作为过渡参考，但最终交互语义收口到 controller。
