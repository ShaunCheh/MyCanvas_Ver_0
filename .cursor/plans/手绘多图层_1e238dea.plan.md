# 手绘多图层分阶段计划

## 已确认前提

- 文档模型采用嵌套结构：`HandDrawingDocument.layers`，每个 `HandDrawingLayer` 内部直接持有自己的 `strokes`。
- `brush`、像素橡皮、套索、移动都只作用 `current active layer`。
- 套索/移动不能跨 layer 建立选区；切换当前 layer 时清空当前选区。
- `hidden` layer 不参与渲染与命中；`locked` layer 继续渲染，但不允许编辑或命中。
- 至少保留 1 个 layer；删除当前 layer 后自动切到相邻 layer。
- 图层相关操作进入统一 `undo / redo` 历史栈。
- V1 只做：新建、删除、重命名、上下移动、显隐、锁定；不做复制层、合并层、透明度、混合模式。
- 旧单层文档在加载时自动包装成默认层（如 `Layer 1`）；iPad 可编辑，macOS 保持只渲染不编辑。

## 阶段 1：Layered 文档模型与版本演进

- 目标：把 `HandDrawingDocument` 从单层 `strokes` 升级为多 layer 文档，同时不破坏旧文档可读性。
- 主要文件：
  - [HandDrawingDocument.swift](/Users/shaun/cloudDev/MyCanvas_Ver_0/MyCanvas_Ver_0/Canvas/HandDrawing/Core/HandDrawingDocument.swift)
  - [HandDrawingDocumentCodec.swift](/Users/shaun/cloudDev/MyCanvas_Ver_0/MyCanvas_Ver_0/Canvas/HandDrawing/Persistence/HandDrawingDocumentCodec.swift)
  - [HandDrawingDocumentLoader.swift](/Users/shaun/cloudDev/MyCanvas_Ver_0/MyCanvas_Ver_0/Canvas/HandDrawing/Editing/HandDrawingDocumentLoader.swift)

  - `HandDrawingDocument` 改成 `paper + layers + activeLayerID + formatVersion`；保留 `stroke.id` 全文档唯一。

  - 保存后落盘统一为新版本格式，旧文档首次保存后完成静默升级。

## 风险与切分原则

- 先做文档模型与 codec，再做 renderer，再做 engine/tool，最后再挂 UI；不要反过来从 UI 开始。
- 图层操作是否进历史、当前层是否进快照、切层是否清选区，这三条必须在 engine 层一次性定清，不能只靠 coordinator 热修。
- `stroke.id` 保持全文档唯一，可以尽量减少选区与历史栈结构改动；如果后续要改为局部唯一，再单独开演进计划，不和 V1 混做。
- 首版不引入 layer opacity / blend mode，是为了让 preview / committed image / thumbnail 的共享渲染契约先稳定下来。
