## 实施方案

- 在 `Platform/Shared/Toolbar` 下新增共享的 toolbar transition / presentation 模型：描述 `visible`、`hidden`、`collapsing`、`expanding` 等过渡阶段，以及从完整 frame 到“顶部固定的正方形”、再到“右侧离屏正方形”的分段几何插值规则。
- 扩展 [MyCanvas_Ver_0/Platform/iOS/Canvas/iOSCanvasToolbarHostView.swift](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/MyCanvas_Ver_0/MyCanvas_Ver_0/Platform/iOS/Canvas/iOSCanvasToolbarHostView.swift) 和 [MyCanvas_Ver_0/Platform/macOS/Canvas/macOSCanvasToolbarHostView.swift](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/MyCanvas_Ver_0/MyCanvas_Ver_0/Platform/macOS/Canvas/macOSCanvasToolbarHostView.swift)：新增接收 transition presentation 的渲染接口，引入内部裁切容器，并让按钮 alpha / scale 跟随 progress 变化；transition 期间禁用交互，steady state 再恢复。
- 改造 [MyCanvas_Ver_0/Platform/iOS/iOSViewController.swift](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/MyCanvas_Ver_0/MyCanvas_Ver_0/Platform/iOS/iOSViewController.swift) 和 [MyCanvas_Ver_0/Platform/macOS/macOSViewController.swift](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/MyCanvas_Ver_0/MyCanvas_Ver_0/Platform/macOS/macOSViewController.swift)：模式切换时立即更新 `workspaceMode`，保证阅读模式的输入/命令门控立刻生效；同时缓存切换前的 toolbar state / frame，再构建切换后的目标 state / target frame，由平台动画驱动分两段完成“收拢”和“滑出/滑入”。
- 过渡几何使用缓存的 `fromFrame` / `toFrame` 做插值，中间不依赖每一帧重新解 steady layout，避免 iOS 侧 history buttons 显隐改变 blocker 后让轨迹抖动。
- 保持 [MyCanvas_Ver_0/Platform/Shared/Toolbar/CanvasToolbarStateBuilder.swift](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/MyCanvas_Ver_0/MyCanvas_Ver_0/Platform/Shared/Toolbar/CanvasToolbarStateBuilder.swift) 继续作为 steady-state 真源，不把动画语义混入现有阅读模式命令/展示规则。

## 验证

- 验证 iOS 与 macOS 的 `编辑 -> 阅读` 和 `阅读 -> 编辑` 两条链路都满足：顶部固定、底部上升、按钮变淡缩小、正方形向右离屏，以及反向还原。
- 验证过渡期间工具栏不可误触发命令，阅读模式的输入门控仍然立即生效。
- 额外检查 iOS 上 history buttons 可见/隐藏切换时，工具栏轨迹没有跳变。
