# 阅读编辑工具栏过渡

## 总体目标

- `编辑 -> 阅读`
- 工具栏顶部固定不变，底部向上收拢，内部按钮同时变淡并缩小。
- 当外框高度收拢到与宽度一致后，工具栏以正方形形态向右移出屏幕。
- `阅读 -> 编辑`
- 以上过程完整倒放。
- 逻辑约束
- `workspaceMode` 仍在点击当帧切换，阅读模式的输入/命令门控不等待动画结束。

## 分阶段计划

### Phase 0：共享过渡契约与几何规则

- 目标
- 把“逻辑模式切换”和“工具栏展示过渡”从语义上拆开，建立 steady state 与 transition state 的边界。
- 主要落点
- `Platform/Shared/Toolbar/` 下新增共享过渡类型和几何 helper，供双端控制器和 Host 共用。
- 计划内容
- 定义过渡阶段：`visible`、`hidden`、`collapsing`、`expanding`，以及必要的子阶段或分段 progress。
- 定义几何规则：
- 完整 frame -> 顶部固定的正方形 frame
- 正方形 frame -> 右侧离屏 frame
- 反向进入时从离屏正方形 -> 正方形 -> 完整 frame
- 明确 steady state 的真源仍然是 `CanvasToolbarStateBuilder`，transition 只是一层 presentation override。
- 明确 transition 期间控制器持有上一态/目标态的 toolbar snapshot，Host 只消费 presentation，不直接推导业务模式。
- 验收口径
- 共享层可以纯函数地从完整 frame 算出收拢 frame、离屏 frame，以及对应的视觉 progress 映射。
- 共享层不引入对 `CanvasEditorSession`、`UIView`、`NSView` 的耦合。

### Phase 1：Toolbar Host 展示层改造

- 目标
- 让双端 Host 具备“在不切 steady hidden 的前提下完成退场/入场动画”的能力。
- 主要文件
- [MyCanvas_Ver_0/Platform/iOS/Canvas/iOSCanvasToolbarHostView.swift](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/MyCanvas_Ver_0/MyCanvas_Ver_0/Platform/iOS/Canvas/iOSCanvasToolbarHostView.swift)
- [MyCanvas_Ver_0/Platform/macOS/Canvas/macOSCanvasToolbarHostView.swift](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/MyCanvas_Ver_0/MyCanvas_Ver_0/Platform/macOS/Canvas/macOSCanvasToolbarHostView.swift)
- 计划内容
- 引入单独的内容裁切容器，让 Host 外框缩高时只裁切内容，而不是直接把按钮栈压缩到产生 Auto Layout 冲突。
- 调整当前按钮栈约束模型，使其可以在“Host 变矮”时保持顶部锚定，不因底部强约束而出现约束告警。
- 新增 transition 渲染接口，让 Host 能在 steady state 之外接收：
- 当前展示用的 toolbar items snapshot
- 按钮内容的 alpha / scale
- 是否禁用交互
- 当前是否处于 transition
- 保留现有 steady `render(_ state: CanvasToolbarState)`，但增加“transition active 时不因 `items.isEmpty` 立刻 hidden”的能力。
- completion 后再切回 steady render，保证 `measuredContentSize()` 和 `isHidden` 恢复到最终业务状态。
- 验收口径
- Host 能显示编辑态按钮快照，同时外框缩到正方形时不报约束冲突。
- 退场过程中按钮逐步变淡和缩小；入场过程中反向恢复。
- transition 期间按钮不可点击，steady state 恢复后可点击。

### Phase 2：iOS 控制器动画编排

- 目标
- 在 iOS 上把模式切换改造成“逻辑立即切换，展示延迟退场/入场”的完整时序。
- 主要文件
- [MyCanvas_Ver_0/Platform/iOS/iOSViewController.swift](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/MyCanvas_Ver_0/MyCanvas_Ver_0/Platform/iOS/iOSViewController.swift)
- 计划内容
- 在模式切换入口把当前 toolbar state 与当前 frame 作为 `from` 快照缓存下来。
- `编辑 -> 阅读`
- 先缓存完整 toolbar 的 state / frame。
- 再立即切换 `workspaceMode`，让阅读模式的输入/命令门控立刻生效。
- 用缓存快照继续渲染 Host，并驱动第一段“顶部固定的收拢动画”。
- 第一段结束后驱动第二段“正方形向右离屏”。
- completion 后才把 Host 切到 steady hidden。
- `阅读 -> 编辑`
- 先立即切换 `workspaceMode`，得到 steady editing toolbar state。
- 用 steady editing state 解出目标完整 frame。
- 根据目标完整 frame 反推离屏正方形起点。
- 先让 Host 以“离屏正方形 + 缩小淡化按钮”的展示态挂载，再执行滑入和展开。
- completion 后切回 steady visible。
- 把 `renderToolbar()`、`updatePreparedToolbarPlacement()`、`applyToolbarFrame(_:)` 这条链改造成“transition active 时优先尊重 transition frame，而不是每次都覆盖成 steady frame”。
- 验收口径
- iOS 上完整满足两段式动画要求。
- 模式切换后，阅读模式输入门控立即生效；动画只是展示延迟，不影响命令语义。
- 动画过程中即使触发额外 layout，也不会把 `toolbarHostView.frame` 跳回 steady frame。

- 目标

- 主要文件

### Phase 5：验证与回归检查

- 目标
- 把需求和潜在回归项一次性验透。
- 验证场景
- `编辑 -> 阅读`
- `阅读 -> 编辑`
- 普通编辑态
- 文字选中导致 `crop` 不显示的工具栏形态
- 裁剪态导致 `crop` 为激活态的工具栏形态
- iOS 上 history buttons 显示/隐藏切换场景

- 验收口径
- 顶部始终固定不变。
- 收拢阶段只有底部向上移动。
- 按钮在收拢过程中同步变淡和缩小。
- 高度收成正方形后才开始向右离屏。
- 反向进入编辑模式时完整倒放。
- 动画期间工具栏不可误触发命令。
- 阅读模式门控立即生效，不因动画延迟而泄漏编辑行为。

1. 先完成 Phase 0，明确共享过渡契约和几何规则。
2. 再完成 Phase 1，给双端 Host 准备好 transition 展示能力。

## 关键时序

1. `编辑 -> 阅读`
2. 缓存当前 toolbar 的 state 和 frame。
3. 立即切换 `workspaceMode`。
4. 用缓存 state 继续显示 toolbar，并执行“收拢到正方形”。
5. 再执行“正方形向右离屏”。
6. completion 后切回 steady hidden，并 reconcile 最终布局。
7. `阅读 -> 编辑`
8. 立即切换 `workspaceMode`。
9. 解出 steady editing toolbar 的目标 state 和目标完整 frame。
10. 从目标 frame 反推离屏正方形起点。
11. 先滑入正方形，再展开到完整 toolbar。
12. completion 后切回 steady visible，并 reconcile 最终布局。

import CoreGraphics

enum CanvasToolbarTransitionDirection: Sendable {
    case toReading
    case toEditing

    var itemStates: [CanvasToolbarItemState]
    var showsBackground: Bool
    var contentAlpha: CGFloat
    var contentScale: CGFloat

    var isInteractive: Bool
}

## 控制器建议新增入口

- `beginToolbarModeTransition(to:)`
- 模式按钮点击后的统一入口，负责决定 `toReading` / `toEditing`。
- `prepareToolbarTransitionContext(direction:)`
- 抓取 `fromState`、`toState`、`fromFrame`、`toFrame`，并计算 `collapsedFrame` / `offscreenFrame`。
- `runToolbarCollapsePhase(...)`
- 第一段动画，只负责顶部固定、底部收拢、按钮淡出缩小。
- `runToolbarSlidePhase(...)`
- 第二段动画，只负责正方形离屏或回屏。
- `finishToolbarModeTransition(...)`
- completion 收口，恢复 steady render，并执行 overlay layout reconcile。
- `cancelAndRebaseToolbarTransitionIfNeeded(targetMode:)`
- 如果用户在动画中再次切换模式，以当前 presentation 为新的起点重新编排，而不是简单丢弃。

## Host 结构改造建议

- 保留现有 `backgroundView` 和 `buttonsStackView`，但中间增加一层内容裁切容器，例如 `contentClipView`。
- `backgroundView` 继续铺满 Host 外框。
- `contentClipView` 锚定 Host 顶部、左右对齐、底部小于等于 Host 底部。
- `buttonsStackView` 顶部锚定 `contentClipView`，底部不要再用强约束钉死到 Host。
- 这样 Host 在“底部向上升”时，真正变化的是 Host 外框和裁切区域，而不是强行压缩按钮本身的 Auto Layout 尺寸。
- 按钮缩小建议走 stack 容器统一 `transform` / `layer` 缩放，而不是逐个重算按钮约束。

## 动画默认参数

- 第一段 `collapse / expand`
- 建议默认 `0.18s`，使用 easeInOut。
- 第二段 `slide out / slide in`
- 建议默认 `0.14s`，使用 easeInOut。
- 按钮 `alpha`
- `1.0 -> 0.0` 与第一段同步完成。
- 按钮 `scale`
- `1.0 -> 0.78` 与第一段同步完成。
- 默认先求“结构正确、轨迹正确”，时长和曲线在功能落地后再调。

## 中断与重入策略

- 如果用户在动画尚未结束时再次点击模式按钮：
- 不等待旧动画完成。
- 立刻停止当前动画，读取当前 presentation frame 和视觉 progress，重建新的 transition context。
- 新动画从“当前屏幕上真实看到的状态”继续，而不是从旧 steady frame 重新开始。
- 如果动画期间触发 `viewDidLayout`、safe area 变化或窗口尺寸变化：
- 不立即改写当前轨迹。
- 仅设置 `pendingToolbarLayoutReconcile = true`。
- completion 后重新走一次 steady `updatePreparedToolbarPlacement()` 和 overlay layout。
- 如果动画开始时拿不到有效 toolbar frame：
- `编辑 -> 阅读` 直接退化为 steady hidden。
- `阅读 -> 编辑` 直接退化为 steady visible。
- 退化路径要显式记录到计划验收中，避免出现半初始化状态。

## Phase 内部拆分

### Phase 0 内部拆分

1. 定义共享过渡类型。
2. 写出收拢正方形和离屏正方形的纯函数几何规则。
3. 明确 progress 到 `frame / alpha / scale / keepsHostVisible` 的映射。
4. 确认收拢正方形边长直接复用 `CanvasToolbarChromeMetrics` 推导，不引入重复常量。

### Phase 1 内部拆分

1. 先重构 Host 内部层级和约束，确保“缩高到正方形”不报约束冲突。
2. 再加 transition presentation 渲染入口。
3. 最后再接按钮淡出缩小和交互禁用。

### Phase 2 / Phase 3 内部拆分

1. 把模式切换按钮入口改造成统一 transition 入口。
2. 把 steady render 与 transition render 的优先级梳理清楚。
3. 再接双段动画。
4. 最后处理 completion 和中断重入。

### Phase 4 内部拆分

1. 收口 `renderToolbar()` 对 transition 的覆盖。
2. 收口 `applyToolbarFrame(_:)` 对 transition frame 的覆盖。
3. 收口 `viewDidLayout` / overlay layout 对动画轨迹的打断。
4. completion 后只做一次最终 reconcile。

## 最终验收清单

- 双端都完成与需求一致的两段式工具栏动画。
- steady state 业务语义不被动画污染，阅读模式输入/命令门控保持立即切换。
- Host 在缩高过程中没有约束冲突和视觉闪烁。
- 动画不会被 `renderToolbar()`、`applyToolbarFrame(_:)`、`viewDidLayout` 或 blocker 变化打断。
- completion 后 toolbar、miniMap、context menu 都能回到正确的 steady layout。
