# 修复 iOS 视口同步

## 目标

修复 iOS 端图片导入后初始出现在左上角、继续拖动后消失的问题。
核心思路是把“视口尺寸变化”的事实从外层控制器轮询，改为由真正持有尺寸的 viewport 视图主动上报，避免 `CanvasCamera.viewportSize` 长期为 `.zero`。

## 根因定位

当前问题集中在以下链路：

- [iOS 宿主控制器](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/MyCanvas_Ver_0/MyCanvas_Ver_0/Platform/iOS/iOSViewController.swift)：`setupCanvasViewport()` 安装 viewport 后立即 `refreshCanvas(...)`，但此时还未保证拿到真实 `bounds.size`。
- [iOS viewport 视图](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/MyCanvas_Ver_0/MyCanvas_Ver_0/Platform/iOS/Canvas/iOSCanvasViewportView.swift)：`layoutSubviews()` 只更新 layer frame，不向外报告自身尺寸变化。
- [共享渲染器](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/MyCanvas_Ver_0/MyCanvas_Ver_0/Canvas/Core/CanvasRenderer.swift)：直接用 `camera.visibleWorldRect` 做可见项裁剪；当 `viewportSize == .zero` 时，这个矩形退化为零尺寸，裁剪会变成“跟随 `camera.center` 的点裁剪”。

## 修改范围

### 1. 调整 iOS 端视口尺寸同步主链路

修改 [iOS viewport 视图](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/MyCanvas_Ver_0/MyCanvas_Ver_0/Platform/iOS/Canvas/iOSCanvasViewportView.swift)：

- 增加 `onViewportSizeChange: ((CGSize) -> Void)?` 回调。
- 在 `layoutSubviews()` 中比较本次 `bounds.size` 与上次记录值。
- 仅当尺寸真实变化时主动上报；以 viewport 自身为“尺寸事实来源”。

修改 [iOS 宿主控制器](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/MyCanvas_Ver_0/MyCanvas_Ver_0/Platform/iOS/iOSViewController.swift)：

- 在 `setupCanvasViewport()` 里接入 `onViewportSizeChange`。
- 收到有效尺寸后统一执行：更新 `camera.viewportSize`、再刷新 snapshot。
- 把 `viewDidLayoutSubviews()` 中现有的轮询式同步降级为 fallback，避免继续依赖外层控制器去猜内层 view 的尺寸时机。

### 2. 阻断零视口参与首帧与交互渲染

修改 [iOS 宿主控制器](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/MyCanvas_Ver_0/MyCanvas_Ver_0/Platform/iOS/iOSViewController.swift)：

- 调整首帧刷新时机，避免在 `camera.viewportSize` 仍为 `.zero` 时执行依赖可见区域裁剪的 `refreshCanvas(...)`。
- 为 `appendImportedImage(...)`、`handlePan(...)`、`handleZoom(...)` 这类会触发渲染的入口增加视口有效性保护，确保零尺寸不会再次进入渲染链路。
- 保留现有调试日志，但补充更聚焦的原因标识，便于区分“未拿到视口”与“正常裁剪为空”。

### 3. 增加共享层轻量护栏，不改几何语义

修改 [共享渲染器](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/MyCanvas_Ver_0/MyCanvas_Ver_0/Canvas/Core/CanvasRenderer.swift)：

- 在进入 `visibleWorldRect` 裁剪前，对无效 viewport 做显式保护。
- 目标不是替代 iOS 主修复，而是避免无效输入被放大成误导性的“点裁剪”行为。

不计划修改 [CanvasCamera](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/MyCanvas_Ver_0/MyCanvas_Ver_0/Canvas/Core/CanvasCamera.swift) 的几何换算公式；该文件当前是在忠实放大错误输入，不是根因。

## 验证要点

- 导入图片后，首帧位置应围绕真实 viewport 中心，不再固定偏到左上角。
- 连续向右下拖动时，只要图片仍在可见范围内，`visibleItems` 不应提前变成 `0`。
- 从相册选择返回、初次布局、后续旋转或安全区变化时，`camera.viewportSize` 不应再次被写成 `.zero`。
- 本次方案仅聚焦 iOS 这条失效链路；macOS 与现有 `.md` 文件不在修改范围内。
