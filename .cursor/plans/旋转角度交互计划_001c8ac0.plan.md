# 旋转角度独立 Overlay 分阶段计划

## 目标

采用 `方案 B`：在现有 `editOverlay` 之外新增独立 `interactionOverlay`，只承载“图片被选中并正在拖动旋转引导线条”时出现的角度指示器。现有选中框、缩放手柄、旋转导线、旋转手柄与命中测试继续留在 [MyCanvas_Ver_0/Canvas/Core/CanvasRenderSnapshot.swift](MyCanvas_Ver_0/Canvas/Core/CanvasRenderSnapshot.swift)、[MyCanvas_Ver_0/Canvas/Core/CanvasRenderer.swift](MyCanvas_Ver_0/Canvas/Core/CanvasRenderer.swift)、[MyCanvas_Ver_0/Platform/iOS/iOSViewController.swift](MyCanvas_Ver_0/Platform/iOS/iOSViewController.swift)、[MyCanvas_Ver_0/Platform/macOS/macOSViewController.swift](MyCanvas_Ver_0/Platform/macOS/macOSViewController.swift) 现有链路中，不在第一轮重构里迁移。

## 架构原则

- 保留 `rotationPreviewState` 负责“图片本体的 draft rotation”，避免影响当前图片预览与 minimap 预览语义。
- 新增 `rotationInteractionState` 负责“是否正在旋转、当前 HUD 是否应显示”，从根因上解决“拖动刚开始但角度未变化时，指示器无法立即出现”的问题。
- 新增 `interactionOverlay` 作为与 `editOverlay` 并列的渲染通道，避免继续把交互 HUD 塞进 selection payload。
- 角度显示语义单独封装到 shared core helper：内部角度继续沿用现有实现，UI 仅负责换算为“正上方为 0°、范围 0~360°”。

## 阶段 1：状态边界拆分

涉及文件：

- [MyCanvas_Ver_0/Canvas/Core/CanvasInlineEditState.swift](MyCanvas_Ver_0/Canvas/Core/CanvasInlineEditState.swift)
- [MyCanvas_Ver_0/Platform/iOS/iOSViewController.swift](MyCanvas_Ver_0/Platform/iOS/iOSViewController.swift)
- [MyCanvas_Ver_0/Platform/macOS/macOSViewController.swift](MyCanvas_Ver_0/Platform/macOS/macOSViewController.swift)

实施内容：

- 在 core transient state 层新增 `CanvasRotationInteractionState`，建议至少包含：`itemID`、`referenceCenter` 或可推导中心、`isActive` 语义所需字段。
- 两个平台 controller 进入 `.rotatingSelectedItem` 时建立 `rotationInteractionState`；在 `pointer up`、`cancel`、`selection change`、`enter crop mode`、`history apply` 等路径清理它。
- 保持现有 `CanvasRotationPreviewState` 的职责不变：仍然只用于驱动图片本体旋转预览。

完成标准：

- 不改现有 hit-test 入口。
- 不改现有 `scene.rotateItem(...)` 提交路径。
- 为后续“拖动一开始立即显示 HUD”提供独立状态源。

## 阶段 2：Snapshot 传输层扩展

涉及文件：

- [MyCanvas_Ver_0/Canvas/Core/CanvasRenderSnapshot.swift](MyCanvas_Ver_0/Canvas/Core/CanvasRenderSnapshot.swift)
- [MyCanvas_Ver_0/Canvas/Core/CanvasRenderer.swift](MyCanvas_Ver_0/Canvas/Core/CanvasRenderer.swift)

实施内容：

- 在 `CanvasRenderSnapshot` 上新增 `interactionOverlay: CanvasInteractionRenderOverlay?`。
- 新增 `CanvasInteractionRenderOverlayPayload` 与 `CanvasRotationInteractionOverlayPayload`，作为与 `CanvasEditRenderOverlay` 平级的新传输结构。
- 第一阶段不要迁移 `CanvasEditSelectionOverlayPayload.rotateAffordance`；现有 controller 仍通过它做旋转手柄命中测试。

建议 payload 字段：

- `itemID`
- `screenCenter`
- `displayDegrees0To360`
- `currentRotationRadians`
- `zeroReference = up`
- `tickStepDegrees = 10`
- `ringRadius`
- `isActive`

完成标准：

- `CanvasRenderSnapshot.empty` 能提供默认空值。
- `editOverlay` 与 `interactionOverlay` 生命周期互不耦合。

## 阶段 3：Renderer 几何与角度语义生成

涉及文件：

- [MyCanvas_Ver_0/Canvas/Core/CanvasRenderer.swift](MyCanvas_Ver_0/Canvas/Core/CanvasRenderer.swift)
- [MyCanvas_Ver_0/Canvas/Core/CanvasGeometry.swift](MyCanvas_Ver_0/Canvas/Core/CanvasGeometry.swift)
- [MyCanvas_Ver_0/Canvas/Core/CanvasImagePresentationResolver.swift](MyCanvas_Ver_0/Canvas/Core/CanvasImagePresentationResolver.swift)

实施内容：

- 在 `CanvasRenderer.makeSnapshot(...)` 中并行生成 `editOverlay` 与 `interactionOverlay`。
- 新增 `makeInteractionOverlay(...)` / `makeRotationInteractionOverlay(...)`，输入为 `scene`、`camera`、`interactionState`、`rotationInteractionState`、`rotationPreviewState`。
- 圆心统一取当前图片的旋转中心，即当前 item 的 `center` 映射到 screen-space；不要从手柄位置反推圆心。
- 环半径建议基于“圆心到当前旋转手柄”的距离计算，并设置最小值夹紧，避免小图时刻度环过小。
- 在 shared helper 中提供：
  - 内部弧度到显示角度 `0~360` 的换算
  - 以“正上方”为 `0°` 的基准换算
  - 需要时提供极坐标点计算，减少双端绘制数学分叉

完成标准：

- renderer 产出的 interaction payload 足够让 viewport 只负责绘制，不再在 controller 里重复算 HUD 几何。
- minimap 继续只依赖 `rotationPreviewState`，不被 HUD 生命周期污染。

## 阶段 4：双端 Viewport 独立 Layer 树接入

涉及文件：

- [MyCanvas_Ver_0/Platform/iOS/Canvas/iOSCanvasViewportView.swift](MyCanvas_Ver_0/Platform/iOS/Canvas/iOSCanvasViewportView.swift)
- [MyCanvas_Ver_0/Platform/macOS/Canvas/macOSCanvasViewportView.swift](MyCanvas_Ver_0/Platform/macOS/Canvas/macOSCanvasViewportView.swift)

实施内容：

- 新增 `interactionOverlayLayer`，不要继续把角度指示器平铺到现有 `overlayLayer` 的 selection/crop 逻辑里。
- 为 interaction overlay 建立独立的 `refreshInteractionOverlay()`、`hideInteractionOverlay()`、`updateInteractionOverlayFramesIfNeeded()`。
- 接入 `apply(_:)`、`layoutSubviews/layout()`、`didMoveToWindow/viewDidMoveToWindow()`、整体隐藏流程。
- 维持推荐层级：刻度环在选中框之上、旋转手柄之下；当前角度指针在刻度环之上；角度文字层在最上面。

建议新增 layer：

- `rotationRingLayer`
- `rotationTickLayer`
- `rotationPointerLayer`
- `rotationTextBackgroundLayer`
- `rotationTextLayer`

完成标准：

- interaction overlay 的显示/隐藏不依赖 `hideSelectionOverlay()`。
- iOS / macOS 的 layer 组织尽量镜像，便于后续维护。

## 阶段 5：视觉实现

涉及文件：

- [MyCanvas_Ver_0/Platform/iOS/Canvas/iOSCanvasViewportView.swift](MyCanvas_Ver_0/Platform/iOS/Canvas/iOSCanvasViewportView.swift)
- [MyCanvas_Ver_0/Platform/macOS/Canvas/macOSCanvasViewportView.swift](MyCanvas_Ver_0/Platform/macOS/Canvas/macOSCanvasViewportView.swift)

实施内容：

- 以 `screenCenter` 为圆心绘制一圈 `0~360°` 刻度环。
- 每 `10°` 一个刻度，总计 `36` 个刻度；第一轮默认所有刻度等权重，避免在未确认视觉规范前过度设计。
- 当前角度用一条指针或高亮刻度表达，基准方向为正上方。
- 同时显示当前角度数值，建议使用 `CATextLayer`，文本由 shared helper 输出稳定格式，例如 `0°`、`90°`、`270°`。
- 文本与路径都要按现有 viewport 习惯处理 `contentsScale` 和禁用隐式动画，避免缩放与拖动时发虚或抖动。

默认视觉决策：

- 角度数值优先固定在圆心上方的环外侧，避免跟随指针绕圈导致阅读抖动。
- 不让角度环参与命中测试；仍由现有旋转手柄负责交互入口。

完成标准：

- 拖动旋转导线时，用户能同时看到圆形刻度环、当前角度方向提示、当前角度数值。
- 角度显示与图片当前实际旋转结果一致，但不改变内部旋转存储语义。

## 阶段 6：生命周期与回归收口

涉及文件：

- [MyCanvas_Ver_0/Platform/iOS/iOSViewController.swift](MyCanvas_Ver_0/Platform/iOS/iOSViewController.swift)
- [MyCanvas_Ver_0/Platform/macOS/macOSViewController.swift](MyCanvas_Ver_0/Platform/macOS/macOSViewController.swift)
- [MyCanvas_Ver_0/Canvas/Core/CanvasRenderer.swift](MyCanvas_Ver_0/Canvas/Core/CanvasRenderer.swift)

实施内容：

- 保证以下路径都能正确显隐：开始旋转、持续旋转、结束提交、取消、切换选中项、进入裁剪模式、撤销/重做、历史快照恢复。
- 保证指示器只在“图片已选中且正在旋转拖动”时出现，普通选中态不常驻显示。
- 检查 `CanvasMiniMapNodeProvider` 与 minimap 渲染链路，仅在需要时适配新增 state；默认不让 minimap 感知 interaction overlay。
- 做双端回归：选中框、缩放、裁剪、拖拽移动、撤销/重做、保存/恢复都不能因为 overlay 新增而回归。

验收清单：

- 旋转开始瞬间即可出现 HUD，即使角度尚未变化。
- 圆心始终跟随当前图片旋转中心。
- 刻度环固定 `36` 个刻度。
- 角度数值始终为 `0~360°`，`0°` 在正上方。
- 释放后 HUD 立即消失。
- iOS / macOS 表现一致。

## 实施顺序建议

建议严格按 `状态边界 -> snapshot 传输 -> renderer 几何 -> viewport layer 脚手架 -> 视觉绘制 -> 生命周期回归` 的顺序推进，不要一开始就把现有 `rotateAffordance` 从 selection overlay 中迁走。这样可以把“新 HUD 引入”和“旧旋转命中链路稳定”分离开，避免一次性改动过多导致旋转入口、选中态绘制和历史提交一起回归。
