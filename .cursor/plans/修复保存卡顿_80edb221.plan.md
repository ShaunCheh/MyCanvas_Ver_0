# 修复保存卡顿与保存调度

## 目标

- 去掉 `select item` 触发的 autosave，避免“切换选中对象后 0.35s 触发重保存”卡住拖动前几帧。
- 保持 `BoardStore.saveBoard(...)` 现有同步实现不变，但把真正的保存执行放到共享的后台串行队列。
- 顺手抽出共享保存调度层，减少 `[MyCanvas_Ver_0/Platform/iOS/iOSViewController.swift](MyCanvas_Ver_0/Platform/iOS/iOSViewController.swift)` 和 `[MyCanvas_Ver_0/Platform/macOS/macOSViewController.swift](MyCanvas_Ver_0/Platform/macOS/macOSViewController.swift)` 里重复的 autosave / manual save 调度代码。

## 当前链路

- iOS/macOS 当前都有同一条链路：`selectItem(...) -> scheduleAutosave(...) -> performAutosave(...) -> persistBoardNow(...) -> BoardStore.saveBoard(...)`。
- `[MyCanvas_Ver_0/Canvas/Storage/BoardStore.swift](MyCanvas_Ver_0/Canvas/Storage/BoardStore.swift)` 的 `saveBoard(...)` 会同步做 PNG 编码和多文件写盘；这部分最适合移到后台。
- `[MyCanvas_Ver_0/Canvas/Core/CanvasScene.swift](MyCanvas_Ver_0/Canvas/Core/CanvasScene.swift)` 是可变引用类型，不适合后台直接读取，所以必须先在主线程拍 `BoardRuntimeState` 快照，再后台保存。

## 目标流转

```mermaid
flowchart LR
  mainState[MainThreadCanvasState] --> snapshot[BoardRuntimeStateSnapshot]
  snapshot --> saveCoordinator[BoardSaveCoordinator]
  saveCoordinator --> saveQueue[SerialBackgroundQueue]
  saveQueue --> boardStore[BoardStore.saveBoard]
  boardStore --> files["board.json + assets"]
```



## 实施步骤

1. 新增共享保存调度层

- 新增 `[MyCanvas_Ver_0/Canvas/Storage/BoardSaveCoordinator.swift](MyCanvas_Ver_0/Canvas/Storage/BoardSaveCoordinator.swift)`。
- 让它持有后台串行 `DispatchQueue`，统一提供“立即保存”和“防抖 autosave”入口。
- 约束：主线程只负责生成 `BoardRuntimeState` 快照；真正的 `BoardStore.saveBoard(...)` 在后台队列执行；completion 回主线程。

1. 收敛控制器里的保存职责

- 更新 `[MyCanvas_Ver_0/Platform/iOS/iOSViewController.swift](MyCanvas_Ver_0/Platform/iOS/iOSViewController.swift)` 与 `[MyCanvas_Ver_0/Platform/macOS/macOSViewController.swift](MyCanvas_Ver_0/Platform/macOS/macOSViewController.swift)`。
- 保留控制器内的 `currentBoardRuntimeState(...)` / `ensureActiveBoardIdentityIfNeeded()` 这类“主线程取快照”逻辑。
- 删除或替换两端重复的 `scheduleAutosave(...)`、`performAutosave(...)`、`persistBoardNow(...)` 调度细节，改为调用共享 `BoardSaveCoordinator`。
- 手动保存按钮继续保留各自 UI 反馈，但底层改为复用同一个共享调度入口。

1. 移除 `select item` autosave

- 在 `[MyCanvas_Ver_0/Platform/iOS/iOSViewController.swift](MyCanvas_Ver_0/Platform/iOS/iOSViewController.swift)` 和 `[MyCanvas_Ver_0/Platform/macOS/macOSViewController.swift](MyCanvas_Ver_0/Platform/macOS/macOSViewController.swift)` 的 `selectItem(withID:)` 中移除 `scheduleAutosave(reason: "select item")`。
- 保留 `append image`、`move item`、`pan`、`zoom`、`configure board state` 等 autosave 触发点。
- 不改 `[MyCanvas_Ver_0/Canvas/Storage/BoardDocument.swift](MyCanvas_Ver_0/Canvas/Storage/BoardDocument.swift)` / `[MyCanvas_Ver_0/Canvas/Storage/BoardDocumentMapper.swift](MyCanvas_Ver_0/Canvas/Storage/BoardDocumentMapper.swift)` 的 `selectedItemID` 持久化语义；只是取消“单独点击选中就立刻保存”。

1. 保持线程边界清晰

- 不把 `[MyCanvas_Ver_0/Canvas/Storage/BoardStore.swift](MyCanvas_Ver_0/Canvas/Storage/BoardStore.swift)` 全量改成 async API，本轮保持它同步、阻塞式，但只在后台串行队列调用。
- 不在后台直接访问 `scene` / `camera` / `interactionState` 等控制器状态，避免和 `[MyCanvas_Ver_0/Canvas/Core/CanvasScene.swift](MyCanvas_Ver_0/Canvas/Core/CanvasScene.swift)` 的无锁可变状态发生竞态。

1. 验证点

- iOS 复现路径：先选中 A，再点 B，随后立刻拖 B；确认不再在切换选中后出现明显短卡。
- 确认手动 `Save` 按钮仍然可用，成功/失败/未选目录反馈不变。
- 确认 autosave 仍覆盖导入图片、拖动图片、平移、缩放、首次配置 board state 等路径。
- 对修改文件跑 lint；如果环境允许，再做一次本地编译验证。

## 范围说明

- 本轮不处理“仅改 `board.json`、不重写资产文件”的进一步优化；先解决你明确要求的两点：后台保存 + 去掉 `select item` autosave。
- 如果这轮落地后 `pan/zoom` 仍有可感知负载，再单独做“增量资产写入”优化会更稳。
