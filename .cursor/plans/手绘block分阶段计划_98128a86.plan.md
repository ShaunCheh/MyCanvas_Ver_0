# 手绘 Block 分阶段计划

## 锁定约束

- 新元素是独立类型，不伪装成 image/text；建议命名为 `handDrawing`。
- 新建默认使用正方形画纸，但纸张规格要可扩展；建议新增 `PaperSpec`，默认 `square`。
- 新建后立即进入 iOS 全屏编辑器；再次编辑走工具栏/上下文菜单 `编辑手绘`。
- 编辑器只支持 Apple Pencil 落笔，手指只负责平移/缩放。
- 画布上的缩放/旋转只改外部几何，不改内部手绘坐标；手绘 block 保持纸张宽高比。
- 每次编辑提交都生成新的 `contentRevision`，以驱动 `board.json` 内容变化、`contentUpdatedAt` 更新以及缩略图缓存失效。
- 预览 PNG 长边上限先定为 `2048px`；空白 block 也要生成可见的白纸预览。
- macOS 只显示，不暴露新增/编辑入口。

## 关键风险与规避

- 最大风险不是 PencilKit，而是“编辑后文件内容变了，但 `board.json` 不变”，这会让保存、缩略图和缓存链全部失效；因此 `contentRevision` 必须作为正式字段进入文档模型。
- 第二个风险是把 handDrawing 强行塞进 image 语义，短期能跑但会把 crop / GIF / video poster 这些 image-only 逻辑一起带进来；因此渲染 payload 与 item 类型都要独立建模。
- 第三个风险是平台能力散落在多个 controller 判断里；应尽早抽一个共享能力判断，避免 iOS/macOS 分支越写越乱。
