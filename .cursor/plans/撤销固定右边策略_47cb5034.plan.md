# 撤销 iOS 固定右边策略计划

## 目标

将 iOS 上下文菜单从“固定显示在触点右边且不 clamp”的行为，恢复到 fixed-right 引入之前的动态选位行为；同时保留 [MyCanvas_Ver_0/Platform/Shared/ContextMenu/CanvasContextMenuHostView.swift](MyCanvas_Ver_0/Platform/Shared/ContextMenu/CanvasContextMenuHostView.swift) 里已经修掉“菜单跳回左上角”的宿主约束化修复。

## 必改点

- 在 [MyCanvas_Ver_0/Platform/Shared/ContextMenu/CanvasContextMenuHostView.swift](MyCanvas_Ver_0/Platform/Shared/ContextMenu/CanvasContextMenuHostView.swift) 的 iOS 分支，把 `layoutConfiguration.placementStyle` 从 `.fixedRightOfAnchor` 恢复成动态样式，按旧行为使用 `.cursorPreferred`；`occlusionPolicy` 先保持 `.allowChromeOverlap`，避免把“允许覆盖 chrome”也一并回退。
- 在 [MyCanvas_Ver_0/Platform/Shared/ContextMenu/CanvasContextMenuState.swift](MyCanvas_Ver_0/Platform/Shared/ContextMenu/CanvasContextMenuState.swift) 中恢复 `allowChromeOverlap` 下的动态候选求解。当前这段实现会直接取 `preferredPlacements(...)`，导致即使撤掉 iOS host 的 fixed-right 配置，也仍然更像“首选候选即返回”，不能真正回到旧的按空间动态选位：

```swift
// 文件路径: MyCanvas_Ver_0/Platform/Shared/ContextMenu/CanvasContextMenuState.swift
// 函数名/类型名: CanvasContextMenuLayoutSolver.resolveMenuFrame(...)
// 功能说明: 当前 allowChromeOverlap 分支跳过动态候选排序，直接走首选列表。
case .allowChromeOverlap:
    blockerRects = []
    placements = preferredPlacements(for: configuration.placementStyle)
```

- 这一步会改成：`allowChromeOverlap` 仍然忽略 `occupiedRects` 作为 blocker，但和 `avoidOverlayChrome` 一样走 `candidatePlacements(...)`，让菜单重新按真实空间在右下、右上、左下、左上之间动态选择，并恢复常规 clamp 行为。

## 明确保留

- 保留 [MyCanvas_Ver_0/Platform/Shared/ContextMenu/CanvasContextMenuHostView.swift](MyCanvas_Ver_0/Platform/Shared/ContextMenu/CanvasContextMenuHostView.swift) 中 `menuLeadingConstraint / menuTopConstraint / menuWidthConstraint / menuHeightConstraint / updateMenuContainerConstraints(_:) / layoutIfNeeded()` 这套宿主修复；这部分修的是“左上角 bug”，和 fixed-right/no-clamp 不是同一问题。
- 保留 [MyCanvas_Ver_0/Platform/iOS/iOSViewController.swift](MyCanvas_Ver_0/Platform/iOS/iOSViewController.swift) 中 `layoutAnchorPoint`、`contextMenuSafeBounds()`、`contextMenuOccupiedRects()`、`convertToContextMenuHost(...)` 这些坐标桥接逻辑。
- 保留 [MyCanvas_Ver_0/Canvas/Core/CanvasContextMenuContext.swift](MyCanvas_Ver_0/Canvas/Core/CanvasContextMenuContext.swift) 里 body/blank 跟随真实触点的锚点语义。

## 预期结果

- iOS 不再“永远固定在触点右边”。
- iOS 重新恢复为基于空间的动态选位，并继续受 `safeBounds` clamp 约束。
- 由于继续保留 `.allowChromeOverlap`，菜单仍可覆盖悬浮按钮和 minimap，只是不再使用 fixed-right/no-clamp。
- 共享 solver 行为会同步影响 macOS 当前的 `.allowChromeOverlap + .cursorPreferred` 路径，所以需要做 macOS 冒烟验证，确认动态选位符合预期。

## 验证

- iOS 在画布中部、右侧边缘、底部边缘、靠近 minimap 和悬浮按钮处长按，确认菜单会动态换边而不是固定右侧。
- iOS 确认菜单不会再次跳回左上角，且点外 dismiss、按钮点击正常。
- macOS 做冒烟验证，确认共享 solver 改动后右键菜单仍能正常动态选位。
