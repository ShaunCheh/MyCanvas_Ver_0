# macOS 首帧视口同步修复计划

## 根因

当前链路里，文档恢复阶段会把 `camera.viewportSize` 重建为 `.zero`，这是设计结果，不是存储损坏；真正的问题是 macOS 平台层没有在 `canvasViewportView` 首次拿到有效尺寸后，稳定地把这个尺寸同步回 `camera`。因此 [MyCanvas_Ver_0/Platform/macOS/macOSViewController.swift](MyCanvas_Ver_0/Platform/macOS/macOSViewController.swift) 会先执行一次 zero-viewport 的 `refreshCanvas(reason: "initial setup")`，而第一次真正成功的尺寸同步反而发生在右键链路中。

## 修复方向

### 1. 给 macOS viewport 补齐尺寸回传机制

在 [MyCanvas_Ver_0/Platform/macOS/Canvas/macOSCanvasViewportView.swift](MyCanvas_Ver_0/Platform/macOS/Canvas/macOSCanvasViewportView.swift) 中引入与 iOS 对齐的 `onViewportSizeChange` / `lastReportedViewportSize`，在 `layout()` 中当 `bounds.size` 变化时主动上报。这样 controller 不再依赖“猜测某个生命周期时机 child bounds 已经有效”，而是由 viewport 自己告诉 controller 尺寸何时可用。

### 2. 在 macOS controller 中把 viewport sync 收敛成正式入口

在 [MyCanvas_Ver_0/Platform/macOS/macOSViewController.swift](MyCanvas_Ver_0/Platform/macOS/macOSViewController.swift) 新增一个对齐 iOS 语义的同步入口，例如 `syncCameraViewportSizeIfNeeded(_ viewportSize: CGSize, source: String)`，由 viewport size callback 驱动。这个入口负责：

- 过滤 zero/invalid size
- 同步 `camera.viewportSize`
- 必要时执行 `configureBoardStateIfNeeded`
- 在尺寸或 board state 真正变化时刷新 canvas

`viewDidLayout` 可以保留成兜底，但不再承担首要同步职责。

### 3. 把 macOS 首帧刷新改成“可延迟”的模式

当前 `setupCanvasViewport()` 里直接 `refreshCanvas(reason: "initial setup")`，会在 zero viewport 上生成首帧 snapshot。需要把这条链路改成类似 iOS 的“请求刷新而不是立即刷新”：

- 如果 viewport size 还不可渲染，就记录 `pendingRefreshReason`
- 等 `onViewportSizeChange` 首次给出有效尺寸时，再消费这次刷新请求

这样第一次主键 hit-test、第一次 right click、以及 `lastRenderSnapshot.editOverlay` 都会建立在真实 viewport 上，不再让 stale snapshot 进入后续链路。

### 4. 明确保持文档层不持久化 viewportSize

[MyCanvas_Ver_0/Canvas/Storage/BoardDocument.swift](MyCanvas_Ver_0/Canvas/Storage/BoardDocument.swift) / [MyCanvas_Ver_0/Canvas/Storage/BoardDocumentMapper.swift](MyCanvas_Ver_0/Canvas/Storage/BoardDocumentMapper.swift) 不需要把 `viewportSize` 持久化到文档中。它本来就依赖当前窗口/平台尺寸，继续在恢复时置零是合理的；修复点应留在 macOS 平台层的首次同步机制，而不是把窗口尺寸写进文档。

## 明确保留

- 保留 [MyCanvas_Ver_0/Canvas/Storage/BoardDocumentMapper.swift](MyCanvas_Ver_0/Canvas/Storage/BoardDocumentMapper.swift) 恢复时 `viewportSize: .zero` 的策略，不把窗口尺寸持久化。
- 保留已存在的 `camera.center / zoomScale` 恢复逻辑。
- 保留之前为菜单修的坐标桥接、宿主约束化、上下文解析与布局逻辑；这次修复不应回退菜单层代码。

## 验证

- 冷启动进入 canvas 后，不进行任何右键，先检查日志/行为：`camera.viewportSize` 应在首次有效 layout 后立即变成非零，且 `initial setup` 不再在 zero viewport 上产出 snapshot。
- 第一次左键选中图片时，`PrimaryPointerInput`、`ContextResolve`、`CanvasRefresh` 都应基于一致的非零 `viewportBounds`。
- 第一次右键时，不应再触发 `sizeChanged=true` 的首次 viewport sync；菜单位置、内容、选中对象都应与左键后的状态一致。
- macOS 冒烟回归：pan/zoom、minimap navigate、selection、context menu。
- 共享层未改行为的 iOS 再做一次编译/冒烟，确认没有副作用。
