# iOS 画布 Indirect Pan 接入计划

## 目标

让 `iPhone Mirroring` / iPadOS 指针环境下的触控板双指滚动，能够像 macOS 一样平移画布，同时不破坏现有 iOS 的单指拖拽、元素拖动、长按菜单、pinch 缩放。

## 架构边界

- 输入适配只改视图层与控制器层：
  - [iOSCanvasViewportView.swift](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/MyCanvas_Ver_0/MyCanvas_Ver_0/Platform/iOS/Canvas/iOSCanvasViewportView.swift)
  - [iOSViewController.swift](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/MyCanvas_Ver_0/MyCanvas_Ver_0/Platform/iOS/iOSViewController.swift)
- 不改运行态/持久化模型层：
  - [CanvasEditorSession.swift](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/MyCanvas_Ver_0/MyCanvas_Ver_0/Canvas/Editing/CanvasEditorSession.swift)
  - [CanvasCamera.swift](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/MyCanvas_Ver_0/MyCanvas_Ver_0/Canvas/Core/CanvasCamera.swift)

## 现状依据

- iOS 视图目前只有 `onPointerDown / onPointerMove / onPointerUp / onLongPress / onZoom`，没有 `onPan` 抽象；现有画布平移依赖单指拖拽空白区进入 `PointerDragState.draggingCanvas`。
- macOS 已经存在独立的 `onPan -> handleIndirectPan -> camera.pan(by:)` 路径，可作为 iOS 对齐目标。
- `CanvasCamera.pan(by:)` 已统一定义了 viewport delta 到 camera center 的变换，iOS indirect pan 应直接复用它，而不是单独发明另一套平移语义。

## 分阶段计划

### 阶段 1：为 iOS 视图层新增独立的 indirect pan 输入通道

在 [iOSCanvasViewportView.swift](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/MyCanvas_Ver_0/MyCanvas_Ver_0/Platform/iOS/Canvas/iOSCanvasViewportView.swift) 中新增与 macOS 同构的 `onPan: ((CGPoint) -> Void)?`。

实施要点：

- 新增一个专用 `UIPanGestureRecognizer`，只负责识别 scroll 类事件。
- 使用 `allowedScrollTypesMask = .continuous` 接 trackpad 双指连续滚动。
- 显式设置 `allowedTouchTypes = []`，确保该 recognizer 不参与 direct touch 拖拽识别，避免与当前 `touchesMoved` 状态机重叠。
- 在 recognizer 的 `.began/.changed` 中读取 `translation(in:)`，立即 `setTranslation(.zero, in: self)`，对外发送增量 `delta`，保持与 macOS `scrollWheel` 的“连续增量”语义一致。
- 不把 indirect pan 状态塞进现有 `TouchInteractionState`，让 direct touch 与 indirect scroll 两套输入并行但解耦。

关键参考：

- `iOSCanvasViewportView` 现有 touch 状态机只面向直触摸。
- `macOSCanvasViewportView` 已有 `onPan` 设计，可直接对齐接口风格。

### 阶段 2：在 iOS 控制器层接入 onPan，并抽取统一平移逻辑

在 [iOSViewController.swift](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/MyCanvas_Ver_0/MyCanvas_Ver_0/Platform/iOS/iOSViewController.swift) 中新增 `canvasViewportView.onPan = { ... }`，并实现 iOS 版 `handleIndirectPan(_:)`。

实施要点：

- 在 `setupCanvasViewport()` 中接线，保持与 macOS `setupCanvasViewport()` 结构同构。
- 抽出公共平移入口，例如 `applyCanvasPan(_ translation: CGPoint, refreshReason: String)`：
  - `camera.pan(by: translation)`
  - 现有 `logPanDispatch(...)`
  - `requestCanvasRefresh(...)`
  - `scheduleAutosave(reason: "pan canvas")`
- 让当前 `panCanvas(from:to:)` 只负责计算 direct touch 的 `translation`，再调用公共平移入口。
- 新增 `handleIndirectPan(_:)`，直接把 scroll delta 送入同一个公共平移入口，避免 direct pan / indirect pan 行为分叉。

这样可以保证：

- 单指拖动画布
- 触控板双指滚动画布
- 后续可能的鼠标滚轮平移

都走同一套 camera / refresh / autosave 逻辑。

### 阶段 3：增加交互保护，避免与现有手势竞争

仍在 [iOSViewController.swift](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/MyCanvas_Ver_0/MyCanvas_Ver_0/Platform/iOS/iOSViewController.swift) 中，为 `handleIndirectPan(_:)` 增加明确的守卫条件。

建议保护策略：

- 先 `syncCameraViewportSizeFromCurrentBoundsIfPossible()`，与其它输入入口一致。
- `guard hasRenderableViewportSize`，避免未布局完成时误操作。
- 当 `contextMenuState != nil` 时，沿用 macOS 语义：先 dismiss，不立即平移。
- 当 `pointerDragState != .idle` 时直接忽略 indirect pan，避免用户正在拖元素/裁剪/旋转时，触控板滚动又改动 camera。
- 不主动取消现有 touch 交互，不把 indirect pan 写入 `pointerDragState`。

这一步的目标不是“让所有输入同时生效”，而是保证优先级清晰：direct manipulation 优先，indirect pan 只在空闲态接管相机移动。

### 阶段 4：校正 delta 方向与平台手感

在 [iOSCanvasViewportView.swift](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/MyCanvas_Ver_0/MyCanvas_Ver_0/Platform/iOS/Canvas/iOSCanvasViewportView.swift) 中确认 `UIPanGestureRecognizer.translation(in:)` 的方向与 [CanvasCamera.swift](/Users/shaun/Library/Mobile Documents/com~~apple~~CloudDocs/Develop/MyCanvas_Ver_0/MyCanvas_Ver_0/Canvas/Core/CanvasCamera.swift) 的 `pan(by:)` 符号约定一致。

实施要点：

- 若实际运行方向正确，则不做额外转换。
- 若发现自然滚动方向与现有 direct drag 手感相反，只在视图层 `handleIndirectPan(_:)` 中翻转 `delta` 符号。
- 不修改 `CanvasCamera.pan(by:)`，因为它已经同时服务 direct drag 和 macOS scroll pan。

## 验证计划

### 功能验证

- 在 iPhone Mirroring 环境下，双指上下/左右滚动可以平移画布。
- 单指拖拽空白区仍能平移画布。
- 单指拖动已选中元素仍只移动元素，不移动画布。
- pinch 缩放仍正常，且不会和 indirect pan 互相吞手势。
- 长按菜单仍能弹出，菜单弹出后滚动不会留下半状态交互。

### 回归验证

- 读取修改文件的 lints，确保未引入新的 Swift 诊断。
- 如项目已有可快速执行的 iOS 构建/测试命令，则至少跑一次相关目标编译，确认 `allowedScrollTypesMask` / `allowedTouchTypes` / recognizer wiring 没有 API 或可用性问题。
- 因部署目标是 `iOS 15.6`，本次实现不需要额外兼容低于 `13.4` 的分支逻辑。

## 风险点

- `translation(in:)` 的方向可能与预期视觉手感不一致，需要真机或 Mirroring 实测确认。
- 如果不正确隔离 touch 与 scroll，`UIPanGestureRecognizer` 会与现有 touch drag 竞争；因此 `allowedTouchTypes = []` 是本方案的关键保护。
- 如果不把 direct pan / indirect pan 收口到同一公共方法，后续容易出现一边刷新/自动保存/日志行为不一致的问题。

## 预期产出

- iOS 画布支持 trackpad 双指滚动平移。
- 现有 touch 状态机保持原状，不把 indirect input 混入 `TouchInteractionState` 或 `PointerDragState`。
- iOS 与 macOS 在 viewport 输入抽象层上更一致，后续维护成本更低。
